## Operational policy

- Agora Chat owns message bodies and roaming history. PostgreSQL stores conversation membership, provider group IDs, and read metadata; it does not mirror message bodies. Configure retention, export, recovery and data residency in the Agora project before production use. The existing service owner `lumolynk_service` controls private groups; clients cannot invite arbitrary members through the LumoLynk UI.
- Workspace removal disables the workspace-specific provider identity before removing it from private groups and committing membership removal. Provider failures block the removal; retry after service recovery. This favors access revocation over pretending that an unavailable provider was synchronized. Removing a DM participant releases its pair key so a subsequent authorized DM starts with new history.
- RTC credentials last 60 seconds; refresh rechecks access every 25 seconds. End/revoke rejects new credentials immediately. Existing provider credentials can remain valid for their remaining lifetime; there is no claim of an instantaneous provider-side kick. Recording/transcripts remain outside this increment.
- Open meetings require a signed-in LumoLynk account. They disclose meeting information and participant names, not the originating workspace ID or directory. They do not grant workspace membership. Scheduled meetings open five minutes before start.
- Desktop's native email/password sign-in transport sends validated JSON requests to the configured API and uses its HTTP-only cookie session. The renderer never receives cookie headers or tokens from Better Auth. No OAuth callback/deep-link exchange exists because this foundation has no OAuth flow. Explicit pasted links support desktop invitation/meeting navigation.
- OS credential persistence fails closed: Linux `basic_text` and unavailable key stores use memory only. Automated mock-encryption tests exercise persistence, invalid ciphertext, renewal/logout races and restart restoration. Actual WSL execution lacks an OS keyring, so a restart requires sign-in here. Windows/macOS secure-store behavior and actual camera/audio/screen capture require native-runner/manual validation.
- Electron's renderer is sandboxed with Node disabled and context isolation. Production uses `lumolynk://app`, bounded main-process API requests, sender validation, an explicit media prompt and source picker, navigation denial and CSP. Electron-vite emits relative asset URLs; a same-origin HTML base makes deep-route reloads work under the custom protocol.
- RTC/Chat SDKs load on demand. The Chat SDK contains an upstream direct-eval probe; CSP remains enforced without `unsafe-eval`. The production build reports the upstream warning. A version-guarded generator derives static protobuf codecs from the installed SDK schema, preserving its wire semantics. Compatibility tests compare zero-valued fields and envelopes against the vendor encoder. Live browser/Electron messaging succeeds under the production CSP. `pnpm --filter @lumolynk/app chat:check` verifies reproducibility; review this integration on SDK upgrades.

## Remaining verification and product limits

Windows/macOS packaging jobs are prepared but have not run on this Linux host. Signing/notarization, installers on target machines, updates, real OS-backed credential restoration, physical camera/audio quality and native screen/portal permissions need platform validation. This WSL host has no protected Linux keyring, so actual session persistence here deliberately uses memory and requires sign-in after restart; mocked-encryption unit tests cover the persistence logic.

Agora is authoritative for message retention, history/export/deletion and disaster recovery. Unread badges currently refresh for the active Messenger connection's recent provider conversations (up to 50); always-on app-wide unread/presence and larger provider-conversation paging remain follow-up work. Email invitations use manual link delivery; the app never claims to have sent invitation mail. Expo needs native views, navigation/media and credential adapters, reusing the existing contracts, domain identities, design tokens and transport boundary. Recording, attachments, rich message editing/search and full presence remain outside the documented MVP.

Provider errors fail closed. RTC tokens have a 60-second maximum remaining lifetime after end/revocation; immediate provider-side ejection is not implemented. Private conversation revocation disables the workspace provider identity before committing membership removal. Current Linux build warnings originate from the vendor Chat eval capability probe and large, lazily loaded SDK chunks; runtime protocol codecs avoid eval without weakening CSP.
